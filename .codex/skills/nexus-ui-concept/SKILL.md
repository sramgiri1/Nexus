# nexus-ui-concept

## Name

NEXUS UI Concept

## Description

Create high-end UI concepts for NEXUS Command Center and related demo surfaces without changing runtime behavior or backend scope.

## When to Use

Use for UI, dashboard, prototype, layout, and investor-demo design work where the goal is concept quality, product clarity, and presentation polish.

## Steps

1. Confirm the task is UI or design focused.
2. Restate the target surface and audience.
3. Keep scope to concept, layout, styling, copy framing, or static prototype unless implementation is explicitly requested.
4. Focus the concept on mission control, agents, tasks, gates, evidence, cost, safety, approvals, release, and demo mode where relevant.
5. Produce a cohesive design direction that improves clarity and perceived product quality.
6. Call out any backend or runtime work that is intentionally out of scope.

## Safety Checks

- Use only for UI and design work.
- Do not change runtime behavior.
- Do not implement backend unless explicitly requested.
- Keep concepts aligned with evidence-first NEXUS operations.

## Allowed Outputs

- UI concepts
- Screen layouts
- Information architecture proposals
- Static prototypes
- Design notes and rationale

## Forbidden Actions

- Runtime changes without explicit approval
- Backend implementation
- Generic admin-dashboard design
- Scope expansion beyond the requested UI surface

## Design Goals

- Premium
- Enterprise-ready
- Command-center feel
- Not a generic admin dashboard
- Investor-demo ready
- Evidence-first UI
