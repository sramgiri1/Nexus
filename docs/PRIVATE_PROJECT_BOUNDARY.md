# Private Project Boundary

Private project work belongs in a separate private repo or a clean private
workspace.

## Rules

- public NEXUS OS materials use `DemoApp` only
- do not put private project data in `dashboard/`, `demo/`, or `reports/`
- do not commit customer data, private business plans, or private product
  details to the public repo
- keep private runtime integrations, credentials, and product-specific code out
  of the public showcase surface

## Historical cleanup note

If older local or historical work includes private project names such as
CareLoop, keep that work out of the public-facing demo surface. If necessary,
create a clean public repo without old history and keep private product work in
separate private repos.
